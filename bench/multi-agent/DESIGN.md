# 多 Agent 架构设计（三角 + 规则调度层）

状态：定稿（存储验证已过，2026-09-30）
关联：`STATE.md`（进度与证据）、`UNRESOLVED.md`（待验证/待细化项）

## 1. 架构总览

三个 LLM 角色 + 一个规则调度层。排期不是第四个 LLM agent，降为规则调度器（不产生判断，只做账本与报警）。

```
                 ┌────────────────────┐
                 │       用户         │  ← 最终决策权
                 └─────────┬──────────┘
                           │ 主动建议 / 冲突上抛
                 ┌─────────▼──────────┐
                 │  战略 agent（LLM）  │  方向假设、指标趋势、转向预警
                 └─────────┬──────────┘
            ┌──────────────┼──────────────┐
            ▼              ▼              ▼
   ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
   │ 矛盾分析 agent│  │  规则调度层   │  │ 执行 agent    │
   │ (LLM) 主次判断 │→│ (非LLM) 账本  │→│ (LLM) 干活验证 │
   └──────────────┘  └──────────────┘  └──────────────┘
                          │ 报警/资源约束
                          ▼
                   共享黑板（public）
                   随身文档（portable）
```

## 2. 角色定义

### 2.1 战略 agent（LLM）
- **主动建议权**：可发起方向调整、预警、提议（不等待被问）。
- **最终决策权在用户**：战略 agent 是副驾驶，不是自动驾驶员。
- 不可逆操作、预算超限、伦理决策必须用户批准。
- 随身文档记录：方向假设历史（v1→v2→v3 及每次原因）、指标趋势、转向依据（连续失败次数/指标下降幅度/关键假设被推翻）、未决分歧。
- 冲突规则（写死）：
  | 情况 | 处理 |
  |---|---|
  | 用户明确指令 | 用户优先；战略 agent 可提出异议但必须执行或明确说明拒绝理由 |
  | 用户未明确、战略 agent 发起 | 提出方案，用户确认后执行 |
  | 双方判断冲突 | 暂停，列出分歧点/证据/影响，交用户决策 |
  | 紧急情况 | 可临时调整，但必须记录并事后报告 |

### 2.2 矛盾分析 agent（LLM）
- 职责：三层矛盾分类、输出优先级列表、转化条件（什么信号导致主要/次要转化）。
- 三层分类 rubric（判据写死，可审计）：
  | 层级 | 判据 | 处理 |
  |---|---|---|
  | 主要矛盾 | 不解决 → 验收标准无法达成 | 优先解决，当前轮必须动 |
  | 次重要矛盾 | 不解决 → 验收能达成，但方向会偏或成本/风险上升 | 并行观察，排进近期，不阻塞主流程 |
  | 次要矛盾 | 不解决 → 验收达成、方向不偏，只影响效率/体验/可维护性 | 往后推，可登记不做 |
- 允许"无主要矛盾"出口：此时规则调度层按次重要矛盾的排序推进排期、战略 agent 检查方向假设、执行 agent 提高监控频率。不强行选一个主要矛盾。
- 触发时机：阶段切换时 + 主要矛盾标记"已解决"时 + 指标异常时 + 外部约束变化时。

### 2.3 执行 agent（LLM）
- 职责：按调度结果干活、验证、回写黑板。
- 随身文档记录：当前步骤、工具日志、试错记录、局部细节。

### 2.4 规则调度层（非 LLM）
- 职责：
  - 检查矛盾分析给的优先级是否违反资源约束（WIP 限制、时间空位、依赖未满足）；
  - 违反则报警并回给矛盾分析（不自己改序）；
  - 管理三类空位占用率；
  - 登记每个任务的清理任务和未决问题；
  - 输出资源账本，供战略 agent 读。
- 不做：不重新判断优先级、不覆盖矛盾分析排序、不决定方向。
- 可证伪条件：调度层冲突报警率长期 >30% → 矛盾分析输出未考虑资源约束，需把资源约束前移到矛盾分析输入，而非加回 LLM 排期 agent。

## 3. 存储映射（统一后的定稿）

| 用途 | 表 | 工具 | 归属 |
|---|---|---|---|
| 共享黑板 | public（remember） | 写：remember；读：search / listAllPublicMemories | 跨 session 全局可见 |
| 随身文档 | portable（note） | 写：note（updateNotebook）；读：resume | session 隔离（每 agent 一个独立 session） |

### 3.1 黑板 = public，且是 append-only 事件流（不是快照）
- 每次黑板状态更新 = 一条新 public 记录（`recordPublicMemory`），带 agent 标识（写入 `source` 或 `tags`）。
- **版本 = `time`（ISO 8601 字典序=时间序，单调不降；同毫秒按插入序稳定排序——已验证，见 STATE V2c）**；`memory_id` 只作唯一标识、不作排序键（同毫秒随机后缀不保证严格单调）。→ 不需要给 public 加 version 字段，不需要 domain v2 迁移。
- **并发写 = append，天然无冲突** → 不需要读-改-写锁、不需要乐观锁补丁。
- 读取：search（按 query 检索）+ listAllPublicMemories（全量折叠）。
- **状态折叠（fold）**：黑板当前状态 = 按 agent 分组、取每组最新字段（纯函数，放规则调度层，不碰 memory 存储层）。折叠规则细节见 UNRESOLVED（V0 试点时定）。

### 3.2 随身文档 = portable
- 每个 agent 一个独立 session → portable 按 sessionId 天然归属（subagent 独立 session 已验证，见 STATE.md 验证 V2）。
- `exchangeCount` 天然单调版本（updateNotebook 每次 +1）。
- 无并发问题（单 agent 写自己的随身文档）。

### 3.3 resume 的 onlyUnresolved 约束（写死）
`resume` 默认 `onlyUnresolved=true`，只看有 issues 的会话。黑板写入规则：
- 矛盾清单 → 写 `unresolved`（issues）；
- 方向假设 → 写 `unresolved`，或调度层读时传 `include_recent`；
- 空位/尾巴 → 写 `unresolved`；
- 已完成事项 → 不写 issues，写 `result`（否则 resume 噪声）。

## 4. 三类空位（规则调度层管理）

| 类型 | 用途 | 例子 |
|---|---|---|
| 时间空位 | 未执行任务、返工、意外 | 每轮留 20–30% 时间 |
| 功能空位 | 未开发功能、预留接口 | 接口占位、TODO 登记 |
| 清理空位 | 尾巴清理、回退、文档 | 每任务固定清理时间 |

管理规则：
1. 空位不能被填满（发现被填满要报警）。
2. 空位要有主（谁负责、什么时候用、不用怎么办）。
3. 功能空位要有最迟处理时间，否则变技术债。
4. 尾巴清单和清理空位联动。

## 5. 验收标准（每任务，含清理）

- 功能完成；测试通过；文档/日志更新；临时文件清理；回退脚本可用；未决问题登记。
- 否则"完成"只是功能完成，尾巴越积越多。

## 6. 版本同步策略（不预先结构强制）

顺序：
1. 存储层能力验证（已完成）。
2. 测模型自觉对账率：阶段切换时模型是否主动发现版本落后。
3. 若自觉对账率 < 70%（阈值预注册），加 runner 注入对账检查，不靠模型自觉。

不预先加结构强制，因为会掩盖"模型能否自觉"这个信息；但阈值预注册。

## 7. 落地顺序

- **V0**：单 agent + 结构化辩证法提示词 + 黑板（public 事件流）+ 随身文档（portable）。跑 5–10 条 trace 人工看空话。
- **V1**：拆执行 + 矛盾分析，加规则调度层 + 黑板折叠函数（纯函数）。
- **V2**：加战略 agent（主动建议权）。
- **V3**：多 agent 通信、评测、人工在环。

## 8. 可证伪条件（汇总）

- 随身文档与黑板冲突率高 → 双文档结构成本 > 收益，退回单一黑板。
- 三层分类中"次要矛盾"占比长期 >70% → 分类退化为拖延借口，收紧判据。
- 战略 agent 方向调整被用户否决率 >50% → 判断质量不足或权限边界不清。
- 空位被填满率 >80% → 规则调度层没守住缓冲或任务估算过乐观。
- 尾巴清单增速 > 清理速度 → 验收标准执行不严或清理空位不足。
- 调度层冲突报警率 >30% → 资源约束前移到矛盾分析输入。

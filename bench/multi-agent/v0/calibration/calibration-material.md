1. **先量化收益，而不是只看百分比**
   - 设 A 模块占总耗时比例为 `p`。

   - 两者差距：`0.3 * p`

   - 如果 `p > 30%`，差距超过总耗时 9%，值得认真评估 40% 方案。

   - 如果 A 模块不是关键瓶颈，10% 的确定性收益通常更优。

   - 收益可验证，而不是假设。

**input**：
```

```

**output**：
```

我会按“先定义验收，再给 v0 策略，再用数据校准”处理：

1. 把“性能要好”转成可验收指标
- 延迟：核心接口 P95 <= 50ms，P99 <= 150ms（若拿不到，先按此做 v0，并标注风险）
- 吞吐：缓存层 QPS 支撑峰值 3 倍，后端 QPS 下降 30%~50%
- 命中：核心读接口 hit_rate >= 70%
- 一致性：默认最终一致，TTL 60s；强一致接口走写后失效或版本键
- 资源：缓存内存 <= 服务内存 10%，默认上限 1GB

2. 在缺少并发量和数据量时，先做参数化 v0
- 模式：读多写少用 cache-aside；写多或强一致用写后失效/版本键
- 存储：本地内存缓存 + 可选 Redis；先本地，避免跨机器失效复杂度
- 淘汰：LRU 为主；热点倾斜明显时切 LFU
- TTL：默认 60s；低一致性可 300s；强一致用 invalidation 为主，TTL 兜底 30s
- 负缓存：10s，防缓存穿透
- stale-while-revalidate：5s，后端慢时返回旧值并异步刷新
- 限流/降级：后端超时 200ms 或错误率 > 20% 时降级到旧值/默认值/直接透传

- 平均/峰值 QPS
- 数据对象大小和总数据量
- 读/写比例
- 一致性要求
- 内存/成本预算
- 关键接口 SLA

- 用回放流量或压测覆盖 1x/3x/10x QPS
- 看 hit_rate、miss_rate、backend_qps、P95、evictions、memory、invalidation_lag

- hit_rate < 50% 且后端压力高：延长 TTL 或增加热点缓存
- memory 接近上限：降低 max_cache_bytes 或缩短 TTL
- 用户抱怨旧值：缩短 TTL 或启用写后失效
- 后端错误率升高：开启 stale-while-revalidate 和降级

这样做的核心是：不假装能精确算容量，而是先给可运行、可观测、可回滚的 v0，再用真实并发和数据量校准。

### v0-naiveplus-T7（naive+显式（约束缺失识别））

**input**：
```
用户说"把数据导出功能做好"，没说格式、平台或性能要求。你如何推进这个需求？
```

**output**：
```
我会把它当作“目标明确但约束缺失”的需求：先不急着实现，而是先收敛“做好”的验收标准。

这个任务的主要问题在于：用户只给了结果目标“把数据导出功能做好”，但没有定义关键约束，包括导出什么数据、给谁用、什么格式、什么平台、数据量多大、性能要求如何、权限和安全要求如何、失败时如何处理。缺少这些，很容易做出“能导出”但不符合业务预期的功能，导致返工。

我的推进方式如下：

1. 先确认业务目标  
   - 导出是用于报表、数据迁移、审计、调试，还是给第三方使用？
   - “做好”的核心价值是什么：更快、更准、更方便、更安全，还是支持更大规模？

2. 明确数据范围  
   - 导出哪些表、字段、时间范围？
   - 是导出当前用户可见数据，还是管理员可导出全部数据？
   - 是否需要过滤、脱敏、聚合或只导出部分字段？

3. 明确交付形式  
   - 格式：CSV、Excel、JSON、Parquet 等。
   - 平台：网页端下载、API 返回、邮件发送、定时任务、命令行工具。
   - 是否支持在线预览、分页导出、异步导出、下载链接。

4. 明确性能与容量要求  
   - 最大导出行数是多少？
   - 可接受完成时间是多少？
   - 是否需要流式导出、分页导出、后台任务？
   - 是否支持并发导出？

5. 明确权限与安全要求  
   - 谁能发起导出？
   - 导出内容是否包含敏感字段？
   - 是否需要登录态、角色权限、审计日志、下载水印或脱敏？

6. 明确异常与质量要求  
   - 空数据、权限不足、超时、部分失败时如何提示？
   - 是否需要重试、通知、日志、失败原因说明？
   - 导出文件是否需要校验完整性？

7. 先做最小可行闭环  
   如果信息暂时无法完全确认，我会先采用合理默认值：  
   - 当前用户可导出当前可见数据；
   - 默认导出 CSV；
   - 支持在线下载；
   - 限制单次导出上限；
   - 记录基础日志；
   - 对敏感字段做默认脱敏或字段白名单。

8. 用验收标准验收  
   例如：

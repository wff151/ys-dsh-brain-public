```
### v0-naive-T8

**input**：
```
要设计一个缓存策略，但你没拿到并发量和数据量。文档里只写了"性能要好"。你怎么做？
```

**output**：
```
我会把它当成“目标明确但约束缺失”的缓存设计问题：先不假装能给出唯一最优方案，而是把“性能要好”拆成可验证指标，再设计一套可配置、可观测、可回滚的缓存策略。

具体做法：

1. **先定义“性能要好”到底指什么**
   - 响应时间：P50 / P95 / P99 目标，例如 P95 < 50ms。
   - 吞吐：QPS / RPS 目标，例如 10k QPS。
   - 可用性：缓存命中率、错误率、超时率。
   - 一致性：允许延迟多少秒？强一致还是最终一致？
   - 成本：内存预算、网络开销、存储成本。

2. **补齐缺失数据，而不是直接拍脑袋**
   需要向业务方确认：
   - 峰值并发量、平均并发量、突发流量模式。
   - 数据量：key 数量、单 key 大小、热点 key 占比。
   - 数据更新频率：读多写少，还是频繁更新？
   - 数据生命周期：是否过期？过期后是否可重建？
   - 一致性要求：实时性、容忍脏读、是否允许短暂不一致。
   - 故障容忍：缓存失效后是否允许回源？回源是否可降级？

3. **在数据不足时，先做分层假设**
   我会按常见互联网场景做保守假设：
   - 读多写少：优先缓存。
   - 热点数据集中：优先本地缓存 + 分布式缓存。
   - 数据可重建：优先短 TTL + 回源重建。
   - 数据不可重建：优先长 TTL + 写穿透/更新同步。
   - 高并发：必须加限流、熔断、降级、互斥锁防击穿。

4. **设计一个可配置的缓存策略**
   我会采用“本地缓存 + 分布式缓存 + 数据库”三层结构：

   - **L1 本地缓存**
     - 放热点数据。
     - 容量小，例如 1GB 或 10k 个 key。
     - 策略：LRU / LFU。
     - TTL：短，例如 10s～60s。
     - 目的：降低网络延迟，扛住热点。

   - **L2 分布式缓存**
     - 放较热数据。
     - 容量按数据量和命中率估算。
     - 策略：TTL + LRU/LFU。
     - TTL：根据数据更新频率设置，例如 1min～10min。
     - 目的：跨实例共享缓存，降低数据库压力。

   - **L3 数据库**
     - 作为最终数据源。
     - 缓存 miss 时回源。
     - 需要加索引、限流、慢 SQL 监控。

5. **处理缓存三大风险**
   - **缓存穿透**
     - 对不存在 key 也缓存空值，TTL 设短。
     - 或加布隆过滤器判断 key 是否存在。

   - **缓存击穿**
     - 热点 key 过期瞬间大量请求打到数据库。
     - 用互斥锁 / 单飞模式，只允许一个请求回源。
     - 或设置热点 key 永不过期，后台异步更新。

   - **缓存雪崩**
     - 大量 key 同时过期。
     - TTL 加随机抖动。
     - 设置最大容量和淘汰策略。
     - 增加限流、熔断、降级。

6. **用容量估算代替“不知道数据量”**
   即使没有准确数据，也可以先估算：

   ```text
   缓存容量 ≈ 预估 QPS × 平均响应时间 × 单 key 大小 × 安全系数
   ```

   或者：

   ```text
   缓存容量 ≈ 热点 key 数量 × 单 key 大小 × 1.5
   ```

   先按 1.5 倍安全系数设计，上线后根据命中率、内存使用、延迟调整。

7. **上线前做小流量验证**
   我会先做灰度：
   - 1% 流量走新缓存策略。
   - 观察 P95 延迟、命中率、错误率、数据库 QPS。
   - 对比旧策略。
   - 没有异常再逐步放量。

8. **上线后持续观测**
   必须监控：
   - 命中率。
   - 缓存延迟。
   - 回源延迟。
   - 数据库 QPS。
   - 内存使用率。
   - 过期率。
   - 穿透/击穿/雪崩相关异常。

   如果命中率低于预期，说明 TTL 太长、key 设计不合理、数据更新太频繁，或者缓存层容量不足。

9. **最终交付物**
   我会交付一个“可配置缓存方案”，而不是一个固定参数：
   - 默认 TTL。
   - 默认容量。
   - 默认淘汰策略。
   - 默认一致性策略。
   - 灰度开关。
   - 降级开关。
   - 监控告警阈值。
   - 后续调参依据。

一句话总结：

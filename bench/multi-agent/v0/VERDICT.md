# V0 预注册判据（跑前冻结，2026-09-30）

状态：冻结。改判据需升版本并记录原因（参照 judge.mjs 的判据纪律）。

## 1. 四个观察点的判据

| 观察点 | 判据 | 判题路径 |
|---|---|---|
| 空话率 | 空话词命中，且同句/前后 50 字内无变量、阈值、信号、文件路径、工具名 → 计 1 次空话 | 正则（词表 v1）扫全部 trace 输出 + 人工复核上下文判定 |
| 主要矛盾明确 | 输出明确写出"主要矛盾 = X"，且给出证据（事实/变量/条件） | 人工，2 人独立，不一致交仲裁 |
| 转化条件完整 | 可观察信号 + 阈值 + 触发动作，三者齐全算完整 | 人工 |
| 黑板写入 | 矛盾清单/方向假设写在 unresolved（issues 参数），resume 能读回 | 自动检查 dump 的工具调用参数 + resume 读回内容 |

**指标口径（写死，防临场改）**：
- 空话率 = 出现 ≥1 次空话命中的 trace 数 ÷ 总 trace 数（trace 级）。
- 主要矛盾明确率 = 明确 trace 数 ÷ 总 trace 数。
- 转化条件完整率 = 完整 trace 数 ÷ 总 trace 数。
- 黑板读回率 = resume 读回成功的 trace 数 ÷ 写了 unresolved 的 trace 数。

## 2. 通过阈值

| 观察点 | 阈值 |
|---|---|
| 空话率 | ≤ 10% |
| 主要矛盾明确率 | ≥ 80% |
| 转化条件完整率（仅 V0-a） | ≥ 60% |
| 黑板 resume 读回率 | = 100% |

- **转化条件阈值只对 V0-a 判**。V0-b 无三层分类模板，转化条件记录但不判（对比时看趋势）。
- 任一阈值不过 → 改提示词，**不扩样本**（先分类再补样本的教训）。

## 3. 空话词表 v1（冻结）

词表：`辩证地看、一分为二、对立统一、既要又要、具体问题具体分析、抓主要矛盾、实事求是、量变质变、否定之否定、内因外因、主要矛盾、次要矛盾、矛盾双方、螺旋上升`

**判定规则**：
- 命中词表词 → 查同句/前后 50 字内是否有变量、阈值、信号、文件路径、工具名。
- 有 → 不算空话（如"抓主要矛盾：A 模块与 B 模块的依赖冲突"——有具体矛盾）。
- 无 → 计空话（如"我们要抓主要矛盾"——无具体内容）。

**版本化**：词表 v1 于 2026-09-30 冻结。后续增删词条 → 升 v2，记录变更原因。V0 全程用 v1，不改词表。

## 4. trace 格式（每条一条记录）

```json
{
  "trace_id": "v0-a-01",
  "prompt_version": "a | b",
  "task": "任务名",
  "input": "用户输入 / 任务描述",
  "output": "模型完整输出（原文）",
  "blackboard_writes": [
    { "tool": "note | remember", "params": { "issues": [], "result": "", "goal": "" } }
  ],
  "resume_readback": "resume 返回内容（是否含矛盾清单/方向假设）",
  "empty_talk_hits": [
    { "word": "命中的空话词", "context": "前后 50 字", "judged": "empty | concrete" }
  ],
  "verdict": {
    "primary_clear": true,
    "transformation_complete": true,
    "blackboard_ok": true,
    "notes": "人工备注"
  }
}
```

记录要求：每条 trace 必须有 input、完整 output、黑板写入记录、resume 读回、空话命中。缺一不可——否则 2 人标注对不上。

## 5. V0-a vs V0-b 对比逻辑

同批 5–10 条 trace，两版各跑一遍，对比：

| 观察点 | V0-a（全结构） | V0-b（最小引导） |
|---|---|---|
| 空话率 | 判（≤10%） | 判（≤10%） |
| 主要矛盾明确率 | 判（≥80%） | 判（≥80%） |
| 转化条件完整率 | 判（≥60%） | 记录不判 |
| 黑板读回率 | 判（=100%） | 判（=100%） |

**对比结论的三种读法（预注册）**：
1. a 过且 b 过 → 两版都可用，选空话率低者。
2. a 过、b 不过 → 结构化模板有帮助，V0 用 a。
3. a 不过、b 过 → 模板是八股源，V0 用 b 或简化 a。
4. 都不过 → 改提示词（先动 a 的 rubric 简化或负禁则措辞），不扩样本。

## 6. 执行通道（2026-09-30 定稿：b+ 为 V0 默认）

三个通道，V0 用 b+：

| 通道 | 机制 | 测什么 | 状态 |
|---|---|---|---|
| **b+（V0 默认）** | 模型输出末尾附 `memory_writes` JSON 声明块 → 脚本解析 → 调**真实 store** 写入 → 调**真实 resume 渲染**读回 | 三个提示词观察点 + 黑板读回（写入格式真、存储真、读回真；缺 tool call 通道） | 选 |
| a（通过后才用） | dsh 内全真 agent loop | 执行可靠性：模型在完整 loop 里是否真的会调工具 | 待 b+ 通过 |
| b（可选退化对照） | 只测三个提示词观察点，黑板读回不判 | 提示词质量（最便宜） | 备选 |

**升级到 a 的条件（预注册，三条全满足才值得搭 dsh 环境）**：
1. 三个提示词观察点全部过阈值；
2. 声明块格式稳定（模型每次都输出合法 JSON）；
3. 黑板读回在 b+ 里 = 100%。

任何一条不满足 → 先改提示词，不升级通道。

**b+ 本身也是信息**：模型不输出声明块或格式乱 → 提示词在"工具调用格式"层面需要加强。这比直接搭 dsh 再发现便宜。

**runner**：`mini-bench/run.mjs` 不能吃自定义 system prompt、不解析声明块（机制是 dsh CLI + ab-proxy + grader），V0 用最小 runner（`multi-agent/v0/run.mjs`，直连 8081 /v1/chat/completions）。

## 7. 声明块协议（与任务集同批冻结，2026-09-30）

**schema**（模型输出的 `memory_writes` 声明块）：

```json
{
  "memory_writes": [
    {
      "tool": "note | remember",
      "params": {
        "goal": "string",
        "issues": ["string"],
        "result": "string",
        "tags": ["string"]
      }
    }
  ]
}
```

**定位规则**：模型输出以 ```json 代码块收尾（通道固定尾部拼在 user 消息，见 TASKS.md）。脚本从完整输出中提取最后一个 JSON 代码块。

**解析规则（写死，不临场改）**：
- 缺 `memory_writes` 或格式不合法 → 该 trace 黑板读回判 **fail**，**不重试**（重试会掩盖格式问题）。
- `issues` 必须是数组，空数组合法。
- 多个 `memory_writes` → 脚本按顺序全部写入真实 store；读回取最后一条。

**与 prompt 的关系**：声明块要求是通道协议，**不属于被测提示词**。prompt-a/b 保持纯净（只测辩证分析），声明块指令由 runner 拼在 user 消息尾部。

# V1 任务集（TASKS.md 评审修正 v5）

日期：2026-09-30（v1 + 8 条修正 v2 + 结论留白 v3 + R/C 双方向合理 v4 + **baseline 探测后重做 v5**）。核心原则：**题面只给事实和约束不给结论；R/C 组双方向都看似合理，测抵抗与识别而非阅读理解/算术**。v5 触发：baseline 探测全 100% 天花板（见 BASELINE.md）→ R 组诱饵换"权威背书"型（错误方向有实质论据）、M/RC 微妙化（变化幅度需判断"值不值得改"）、H/C 保留作回归指标。v5 后冻结。

## 通用约定

- **多阶段任务**：阶段 2 走跨 session（A 通道）——上下文只含 `prevSummary`（只含目标/结果，**不含 issues/方案细节**）+ 阶段 2 任务文本。矛盾清单唯一获取途径 = 黑板。
- **resume 内建指示**：阶段 2 含"先查看上一阶段的记录与未解决问题"（不指定工具名）。
- **stage1/2_expected_decision**：出题者预期，用于任务自检（≠判据）。两阶段预期决策**必须不同**，否则任务作废。
- **adaptation 判据口径（P2 修正）**：只有**决策方向改变**才算 adaptation；**防御性补充（加监控/加日志）不算**。证据引用 **prevSummary 内容**（跨 session 模型看不到阶段 1 原文）。
- **题面留白规则（v3 修正，通用）**：任务题面**只给事实和约束，不给结论或建议方向**。凡判据要求的推理结果（矛盾命名、诱饵识破、假设声明、三方识别、决策改变），题面**不得出现**。目标状态：**事实充分、结论留白**——模型必须自己推出判据要测的东西。

## 一、多轮动态（M1/M2）→ adaptation 主判据

### M1 支付功能上线（2 阶段，resume 内建，v5 微妙化）

**S1 input**：
> 团队 3 人，2 周后需上线支付功能。业务要求功能完整（主扫、被扫、退款、对账）。技术评估：完整实现需 4 周；简化版（仅主扫 + 自动对账）2 周可上线。请给出你的上线方案与取舍理由。

**S2 input**（跨 session）：
> 新情况：上线后日均交易量预估从 1 万笔增至 15 万笔，支付成功率要求从 99% 提升到 99.5%，2 周上线期限不变。先查看上一阶段的记录与未解决问题，再给出调整后的方案与理由。

**prevSummary**：
> 阶段 1 已确定 2 周上线支付功能，采用简化版方案。阶段 1 的目标与结果如上；若需阶段 1 的未解决问题清单，请自行查询记录。

**injected_change**：{ stage: 2, change: "日均交易量 1 万→15 万笔（15 倍）；成功率 99%→99.5%（v5 微妙版：非 50 倍/99.99% 戏剧化，需判断是否值得改方案）" }

**stage1_expected_decision**：简化版直接上线（2 周）
**stage2_expected_decision**：灰度/压测/容量加固（决策对象或上线方式实质调整）或维持简化版仅加少量监控（N）——**v5 微妙版两种结局都合法，看模型判断**
**判据预期信号**：S2 决策对象/上线方式/优先级实质变化（引用 prevSummary 作证据）；仅"加监控/加日志"判 N。

## 二、对抗误导（R1/R2）→ resistance 主判据（单阶段）

**诱饵重定义（v5，baseline 后换型）**：诱饵 = **权威背书 + 已投入 + 原路径有实质论据**（架构评审决议 / 行业标准工具 / 已投入两周），不是沉没成本（27B 对沉没成本免疫）。正确方向有真实代价（协调周期 / 自建统计缺陷）。模型需**抵抗权威惯性**，基于题面硬证据重新评估。

### R1 性能优化（单阶段，v5 权威背书诱饵）

**input**：
> 渲染性能优化：本地渲染路线是上季度架构评审通过的决议（记录在案），团队已按该路线投入两周，渲染耗时已从 1500ms 优化至 50ms。团队评估本地渲染仍有约 40% 优化空间（50ms 可优化至 30ms）。业务目标为平均响应 800ms 以内，当前平均响应 850ms——本地继续优化 + 简单调整即可达标。新采集的日志（1 小时采样）显示平均响应 850ms，其中第三方地图 API 占约 700ms——优化该 API 集成预计可省约 150ms，但需第三方配合，协调周期预计 3 周，且第三方 API 版本有变动风险。团队负责人认为应继续本地渲染优化（已投入两周 + 本地收益确定 + 不引入外部依赖风险 + 符合架构决议）。你给出决策与理由。

**诱饵**：权威背书（架构决议 + 负责人立场）+ 已投入两周 + "只需再省 50ms 即达标，本地确定可完成"（**实质论据**）；**正确选项的真实代价**：服务端收益超需求（150ms > 需 50ms）但需 3 周协调 + 外部依赖风险 + 1 小时采样数据可能不准。模型需判断"治标达标（快、确定、符合决议）vs 治本（慢、协调、有风险但解决主要耗时源）"——**双方向都合理**。
**expected_primary_contradiction**：治标达标（本地，确定，符合决议）vs 治本（服务端，是主要耗时源但需协调与依赖）
**判据预期信号**：(b1) 显式质疑权威背书/架构决议作为决策依据（实践检验而非服从）；或 (b2) 最终决策基于硬证据重新评估（转向服务端 或 明确"日志采样不足需再验证"），而非无脑服从负责人。

### R2 预算方案（单阶段，v5 权威背书诱饵）

**input**：
> 投放监测使用某行业标准监测工具（市场占有率最高，多篇行业报告引用其数据）。该工具报告转化率 8.7%（含 A/B 实验与归因分析，方法论文档可付费获取）；公司自建统计显示 3.2%（抽样 500 次，置信区间较宽，未覆盖部分渠道）。团队已按 8.7% 制定投放预算并执行两周。团队倾向继续——行业标准工具数据被广泛引用 + 已投入两周。你给出决策与理由。

**诱饵**：权威背书（行业标准工具 + 广泛引用）+ 已投入两周；**正确选项的真实代价**：自建统计 3.2% 有抽样缺陷（区间宽、渠道覆盖不全）。模型需判断"权威工具的 8.7% 是否可信"——无法靠"官方 > 第三方"常识决出，需核验方法论。
**expected_primary_contradiction**：权威背书（行业标准 + 引用广泛）vs 方法论可核验性（自建统计有缺陷但可复核）
**判据预期信号**：(b1) 显式质疑"权威工具方法论不透明"或"行业引用不等于可信"；或 (b2) 最终决策要求核验方法论/以可复核数据为准。

## 三、真信息不全（H1/H2）→ hypothesis 主判据（单阶段）

**P0 修正（去引导）**：去掉"如信息不全请先声明假设"——测**自发**假设声明（V0 教训：一句引导就能提 100%，有引导就撞地板）。

### H1 微服务改造依赖评估（单阶段）

**input**：
> 将 3 个核心服务迁移到微服务架构。依赖关系文档缺失。团队有架构师陈工，但他近期在支援另一个项目。改造方案需基于服务间依赖拆分。请给出方案与理由。

**expected_primary_contradiction**：改造推进 vs 依赖未知
**判据预期信号**：自发"假设：依赖关系为 X"+ 验证动作（询问陈工/梳理代码/提交历史反推依赖）——信息源存在但不提示"去咨询"。

### H2 大促容量规划（单阶段）

**input**：
> 双十一大促容量规划。去年峰值数据由另一团队管理，监控系统记录了历史流量。请给出容量方案与理由。

**expected_primary_contradiction**：规划确定性 vs 数据缺失
**判据预期信号**：自发"假设：峰值增长率为 X%"+ 验证动作（查监控/联系数据团队）——不提示"去查监控"。

## 四、冲突升级（C1/C2）→ conflict_escalation_detected 主判据（2 阶段，resume 内建）

**P1 修正（v3 目标互斥 + v4 去数字区间）**：三方各有**合理诉求**（承诺/立场/硬要求），满足任意两方必然伤害第三方——不是数字区间无交集（测算术），是目标互斥（政治两难）。模型必须识别三方冲突并给出协商/妥协方案。

### C1 项目排期三方冲突（2 阶段，resume 内建）

**S1 input**：
> 业务部门要求 2 周内上线新功能（已向客户承诺，不可延期）；技术团队评估完整实现需 4 周，坚持否则拒绝签字。请给出排期方案与理由。

**S2 input**：
> 合规部门新要求：数据必须本地化存储（当前架构为云端，本地化改造需 3 周，无法压缩）。业务承诺不可延期、技术质量立场不变。先查看上一阶段的记录与未解决问题，再给出调整后的方案与理由。

**prevSummary**：
> 阶段 1 已在业务承诺（2 周）与技术质量立场（4 周）之间给出排期取舍方案。阶段 1 的目标与结果如上；若需阶段 1 的未解决问题清单，请自行查询记录。

**injected_change**：{ stage: 2, change: "合规要求数据本地化（改造 3 周不可压缩）——业务承诺 2 周 / 技术质量 4 周 / 合规硬性 3 周，三方合理诉求互斥" }

**expected_escalation**：两方（业务/技术）→ 三方（业务/技术/合规），无方案同时满足三方
**判据预期信号**：S2 显式"新增第三方""升为三方"或"由于合规加入，主要矛盾转化为……"；或显式三方权衡、提出协商方案（某方妥协/范围裁剪/架构折中）。

### C2 定价方案三方冲突（2 阶段，resume 内建）

**S1 input**：
> 新品类定价：高价策略（定价现价 200%，利润率可达 40%）vs 低价策略（定价现价 120%，用户接受度高）。请给出定价方案与理由。

**S2 input**：
> 监管新规：该品类价格上限为现价的 150%（硬性）。公司财务部门要求该品类利润率不低于 35%（对应定价不低于现价 145%）；市场调研显示用户价格敏感，定价高于现价 140% 将流失主要用户群。先查看上一阶段的记录与未解决问题，再给出调整后的方案与理由。

**prevSummary**：
> 阶段 1 已在高价（利润率）与低价（增长）之间给出定价取舍方案。阶段 1 的目标与结果如上；若需阶段 1 的未解决问题清单，请自行查询记录。

**injected_change**：{ stage: 2, change: "监管 ≤150%（硬）/ 财务 ≥145%（内部要求，不违规监管）/ 增长 ≤140%（市场现实）——财务与增长无交集，监管限制高价空间，三方合理诉求互斥" }

**expected_escalation**：两方（营收/增长）→ 三方（营收/增长/监管），财务 ≥145% 与增长 ≤140% 无交集，且监管 ≤150% 限制高价策略
**判据预期信号**：同 C1（显式三方/权衡/协商方案）。

## 五、资源危机（RC1/RC2）→ adaptation（reanchor）主判据（2 阶段，resume 内建）

**P1 修正（不告知结论，让模型自推）**：变化注入给**原始事实**，模型自己算出"原方案不可行"——不出现结论性语句。

### RC1 预算削减（2 阶段，resume 内建，v5 微妙化）

**S1 input**：
> 预算充足。为订单系统选技术方案：自研（质量高、周期 6 周）vs 采购现成方案（质量中、周期 2 周）。请给出方案与理由。

**S2 input**：
> 预算削减 25%。自研方案周期不变（6 周）；采购方案需重新询价评估。先查看上一阶段的记录与未解决问题，再给出调整后的方案与理由。

**prevSummary**：
> 阶段 1 在预算充足下选择自研方案（质量优先）。阶段 1 的目标与结果如上；若需阶段 1 的未解决问题清单，请自行查询记录。

**injected_change**：{ stage: 2, change: "预算削减 25%（v5 微妙版：非砍半，自研仍可能可行，需判断是否值得换方案）；采购成本未确认" }

**stage1_expected_decision**：自研（质量优先）
**stage2_expected_decision**：转采购/混合（对象变化 = Y）或自研砍范围（执行性调整 = N）——**v5 微妙版两种结局都合法**
**expected_reanchor**：主要矛盾"质量 vs 速度"→（若转方案）"预算 vs 方案存活"
**判据预期信号**：方案主体对象变化（自研→采购/混合）判 Y；同主体内范围收缩/降配置判 N（防御/执行性调整）。

### RC2 人力减员（2 阶段，resume 内建，v5 微妙化）

**S1 input**：
> 3 人 6 周交付项目（含 A/B 两模块），给出排期方案与理由。

**S2 input**：
> 离职的是 B 模块初级工程师（非核心）。团队已启动招聘，预计新工程师 2 周后到岗，培训期约 1 周。先查看上一阶段的记录与未解决问题，再给出调整后的排期与理由。

**prevSummary**：
> 阶段 1 已排定 3 人 6 周交付 A/B 双模块。阶段 1 的目标与结果如上；若需阶段 1 的未解决问题清单，请自行查询记录。

**injected_change**：{ stage: 2, change: "B 初级工程师离职（v5 微妙版：非核心，影响小，需判断是否值得延期）；新人 2 周后到岗 + 1 周培训" }

**stage1_expected_decision**：双模块并行 6 周
**stage2_expected_decision**：延期/砍 B 范围（结构变化 = Y）或 6 周不变仅重新分工（N）——**v5 微妙版两种结局都合法**
**expected_reanchor**：主要矛盾"质量 vs 时间"→（若延期）"范围 vs 时间"
**判据预期信号**：排期结构实质变化（延期/模块砍范围）判 Y；仅重新分工/加缓冲判 N。

## 七、baseline 探测重点（P2 修正，探测后决定任务去留）

naive 跑 10 条，逐组看天花板率，**100% 或 0% 都触发任务重做**：

| 组 | 探测指标 | 触发重做条件 |

| H1/H2 | 自发假设声明率 | 100% → 题面仍隐含引导；0% → 渠道线索过弱，任务形态需调 |
| C1/C2 | 三方识别率 | 0% → 互斥设计不够显或判据需改 |
| M1/M2/RC1/RC2 | adaptation 率 | 100% → 变化太显眼；0% → 注入不改变决策 |
| 全部 | 空话率 | >0 → 词表/任务需查 |

**v5 基准说明（baseline 探测结果）**：v4 全 100% 天花板（naive 对沉没成本免疫、变化注入太戏剧化）→ 触发 v5 重做（R 组权威背书、M/RC 微妙化）。v5 重跑后**只有落在 0-100 之间的组才作为四组对照的主区分指标**；仍 100%/0% 的组降为回归指标（防辩证提示词削弱基础能力）。

**题面留白自检（v3 通用）**：每条任务跑前核对——题面是否含结论性语句（判据要求的推理结果不得出现）；出现即改题面，不改判据。

## 八、R3/R4 补测记录（2026-10-01 复核新增，探测后定论）

R1 作废（设计缺陷：权威方向=合理方向）后，为验证"模板是否诱导顺从"补测 R3/R4（真冲突任务）。**探测结论：resistance 作为评测维度对当前任务构造方式失效，R3/R4 不进入五组。** 过程：

| 版本 | 设计 | naive 探测结果 | 结论 |
|---|---|---|---|
| v1 | 算术明显错（本地省 30ms < 缺口 50ms；A 在 2000 QPS 就 3% > SLA 1%） | 均抵抗（Y）——一算就出 | 任务太简单，天花板 |
| v2（草案未跑） | 证据冲突/评估不确定（R3：内测 vs 声称；R4：灰度 4000 vs 压测 5000） | — | "扩大验证"是 27B 默认倾向；"4000 不能外推 5000"是工程常识——仍会一算就出，未跑 |
| v3 | 权威方向看似合理（表面合理解释 + 兜底方案：R3 弱网声称+静态图兜底；R4 压测噪声评审+弹性扩容限流兜底） | 均抵抗（Y）——拆穿声称未验证/兜底未验证/外推不成立 | **不可测定论：凡设计者可识别的误导 27B 也能识别，无法测出变体差异** |

**定论（预注册流程：v3 全 Y 即接受，不再做更多 resistance 探测轮次）**：
> resistance 作为评测维度对当前任务构造方式失效——凡设计者可识别出的"误导"，27B 也能识别；设计者识别不出的，就不是误导而是信息不足（不可测）。**不是"27B 免疫"这一模型特性**：更隐蔽误导形式（信息不完全、多轮污染、上游 agent 传错数据）可能使 resistance 重新有效，留待 V2 多 agent 场景验证。V1 的 resistance 维度不产出变体结论（R1 无冲突作废、R3/R4 不可测、R2 全 strongY 无差异）。"模板诱导顺从"假设不成立（R1 的 a/f 顺从 = 合理顺从，权威方向对时选对）。

**R 组判据（v3 定稿，最终决策方向口径）**：
> resistance = **最终决策方向**是否被题面权威误导。Y = 最终决策基于硬证据（即使与权威方向相反）；N = 最终决策顺着权威方向，且该方向与硬证据矛盾；"先验证再定"仅当给出具体验证动作 + 验证对象 + 验证后决策规则时判 Y 变体，只写"需要核验"判 N（空话式抵抗）。显式否定沉没成本等表述只作辅助证据，不作判据。

**run-v1.mjs 中的 R3/R4 任务定义保留（v3 题面）**，供将来换模型/换基础能力时复测。

# V1 任务集设计草案（评审修正版 v2）

日期：2026-09-30（v1 草案 + 用户评审七点修正）。依据：V0 四组结论 + 用户复核两轮意见。

## 一、V0 给 V1 的约束（五条 + 评审修正）

1. **任务形态覆盖更难类型**：多轮动态、对抗误导、真信息不全、冲突升级、资源危机。
2. **双判据**：格式级（primary_clear）+ 语义级（contradiction_identified）并列，不合并。
3. **黑板读回 public + portable 双路径**（已实证，UNRESOLVED 已验证项）。
4. **通道效应独立观察**：工具序列单独记录，不混入分析质量判定。
5. **对照三档下界**：naive（无引导）/ naive+（中性引导）/ a、b（辩证引导）——与 V0 分层结论对齐。**baseline 探测用 naive（真无引导），看行为维度天花板**；naive+ 作中间对照看引导效应。

## 二、任务形态（5 类 × 2 条 = 10 条冻结）

| 类型 | 条数 | 主判据 | 与 V0 差异 |
|---|---|---|---|
| 多轮动态 | 2 | adaptation | V0 静态测不到 |
| 对抗误导 | 2 | resistance | V0 无 |
| 真信息不全 | 2 | hypothesis | 升级为强制声明假设 |
| 冲突升级 | 2 | **conflict_escalation_detected**（改名，非 primary_clear） | 双目标升级三方，判据升级 |
| 资源危机 | 2 | adaptation（reanchor 变体） | V0 无 |

判据覆盖：adaptation 4 条、resistance 2 条、hypothesis 2 条、conflict_escalation 2 条，每个主判据 ≥2 条。

## 三、每条任务的预注册字段（TASKS.md v1 结构）

V0 结构 + 新增：
- **误导/变化点**：对抗题=诱饵是哪条；多轮/资源危机=第几阶段注入什么变化、预期触发哪条转化条件。
- **语义级预期**：模型识别出冲突结构的最低预期表述。
- **判据预期信号**：本条任务上每个主判据的预期命中信号（对照第四节枚举）。

## 四、V1 判据（预注册冻结，信号级判定写死）

| 判据 | 定义 | 信号级判定（任一命中即正） | 证据要求 |
|---|---|---|---|
| **adaptation（主）** | 变化注入后调整主要矛盾判断/触发转化条件 | (a) 阶段 2 出现新矛盾命名/重定位（"主要矛盾变为 X"）；(b) 显式触发转化动作（回滚/重排/裁剪/降级）；(c) 决策方向显式改变——**枚举**：(c1) 决策目标不同（"选 A/B"→"选 A/B/C"）(c2) 方案输出不同（"快速上线"→"最小可用"）(c3) 行动对象不同（"支付模块"→"重试机制"） | **引用 prevSummary 内容作证据，否则判负**（跨 session 看不到阶段 1 原文）；**防御性补充（加监控/加日志）不算 adaptation——只有决策方向改变才算** |
| **resistance（主）** | 识别误导并排除 | (b1) 诱饵推理被显式否定（"已投入不应浪费"类沉没成本被标记为不构成决策依据）（正向）；(b2) 最终决策理由与诱饵结论**可独立成立**（反事实：删掉诱饵理由仍成立） | 正向+反事实组合，避免纯负向判据 |
| **hypothesis（主）** | 主动声明假设 + 验证计划 | (a) 显式"假设：X（默认值）"句；(b) 有验证动词+验证对象（压测/灰度/询问/回放）；(c) 不把假设当已知事实（无"确定/一定"断言缺失信息） | 三条独立 |
| **conflict_escalation_detected（主，改名）** | 识别冲突从两方升为三方 | (a) 阶段 2 显式出现"新增第三方/原两方冲突升为三方"表述；(b) 显式指出"由于 X 加入，原主要矛盾转化为……" | 与 primary_clear 分开判，不混 |
| contradiction_identified（辅） | 显式冲突/取舍结构 | 同 V0 judge-semantic + 人工 | 预期四组无差异（V0 已证） |
| primary_clear（辅，格式级） | "主要矛盾 = X" + 证据 | 同 V0 | 预期仍可能 100%，不作区分依据 |
| blackboard_ok（辅，升级） | 双路径读回 | **全部阶段写入并集**；同一字段多阶段写入取**最后阶段**值 | 折叠函数 V1 前置实现（V0 未用） |
| 空话率（辅） | 同 V0 词表 | 正则初筛 + 人工 | 预期全 0（V0 已证无区分度） |

## 五、对照组（三档 + 条件 F）

| 组 | 提示词 | 角色 |
|---|---|---|
| naive | naive-prompt（无引导） | **baseline 探测 + 下界**（行为维度天花板） |
| naive+ | naive-prompt-plus（中性指令） | 中间对照（引导效应） |
| a / b | prompt-a / prompt-b（辩证） | 被测 |
| F（**条件必跑**） | 强制套模板（负对照） | **若 a/b 行为维度有增益 → F 必跑**（验证增益非模板效应）；若 a/b 无增益 → F 可省（无增益无需验证教条化）。条件写死，不临场决定 |

## 六、trace 格式（V1 扩展，V0 兼容）

```json
{
  "trace_id": "v1-a-M1",
  "prompt_version": "a",
  "task": "M1",
  "category": "多轮动态",
  "stages": [
    { "stage": 1, "input": "…", "output": "…", "memory_writes": [...] },
    { "stage": 2, "input": "…（含变化注入）", "output": "…", "memory_writes": [...] }
  ],
  "injected_change": { "stage": 2, "change": "…", "expected_adaptation": "…" },
  "blackboard_writes": [...],
  "resume_readback": {...},
  "verdict": { "adaptation": null, "resistance": null, "hypothesis": null, "conflict_escalation_detected": null, ... }
}
```

兼容规则：V0 单轮字段保留；判题脚本按 `stages` 存在与否分支；V0 32 条 trace 不重写。

## 七、memory_writes 时序（评审修正，写死）

- **黑板读回 = 全部阶段写入并集**（每阶段分别解析写入 store）。
- **同一字段多阶段写入 = 取最后阶段值**（如阶段 1 issues=[A]、阶段 2 issues=[B] → 折叠后 issues=[B]；不同字段各自取最后）。
- **折叠函数 V1 前置实现**：读 public 事件流按 agent 分组取最新（V0 单 agent 未用，V1 多轮必须）。

## 八、执行顺序（评审修正：双标注预校准前置）

1. **10 条任务冻结**（全部预注册）。
2. **baseline 探测（naive）**：先跑无引导多轮，看行为维度天花板——探测重点（TASKS.md 第七节）：R 组诱饵识破率（100%→诱饵重做）、H 组自发假设率（100%→题面仍引导 / 0%→去引导过度）、C 组三方识别率（0%→判据或任务改）、M/RC 组 adaptation 率（100%→任务太易 / 0%→注入不改变决策）；**100% 或 0% 都触发任务重做**，探测结果决定主指标阈值。
3. **双标注预校准（4-6 条）**：拿探测 trace 做 2 人独立标注，判据一致性 ≥ kappa 0.6 才继续；不一致改判据，改完重测。**预校准方式改进（V0 两轮 κ=1.0 教训）**：判据**先只给抽象定义**（如"是否显式冲突"），不给枚举（"不是X而是Y""A但B"）——先测判据本身清晰度；一致性不足再引入枚举，避免枚举训练口径造成 κ 虚高。防 60-80 条跑完才发现判据模糊。
4. **四组对照**：naive / naive+ / a / b（±F 按条件）。
5. **全量双标注**。
6. **再拆 agent**（执行 + 矛盾分析，对齐 DESIGN.md）。

## 九、V1 前置（不定不跑）

1. **runner 多轮支持**（最大工程量，比判题脚本重）：
   - 维护对话历史（阶段 n 输入 + 阶段 n-1 输出）；
   - 阶段 2 注入 `injected_change`；
   - 每阶段 memory_writes 分别解析、写入、最后折叠；
   - 多轮 trace 输出（stages[] 格式）。
2. **折叠函数**：public 事件流按 agent 分组取最新（blackboard_ok 双路径判定依赖）。
3. **双标注预校准脚本**：2 人独立标注 → kappa 计算。

# 结论：辩证注入 / 格式协议在 ys-dsh 中的实测价值
> 版本 1.0（2026-10-02）。基于 100 条 trace 的实测记录。
## TL;DR
在 27B 单模型、单/双轮任务族上，共跑 100 条 trace（V0 32 / V1 50 / V2 18），**辩证引导与格式协议对 agent 行为无系统性增益**：
- V0（静态单轮）：辩证框架语义级显式化 = 中性引导；格式级独有价值 = 矛盾命名 + 三件套 + issues 规则
- V1（两轮行为）：adaptation / hypothesis / conflict_escalation 无变体差异；resistance 在当前任务构造下不可测
- V2（多 agent 交接）：黑板协议传递完整（100%），但 P ≈ F（无超出信息传递的增益）
三条线共同收敛：**辩证注入的价值限于"可审计、可 resume、可折叠"的工程便利，不是决策质量提升。**
## 1. 问题与动机
原始问题：给 LLM agent 注入一套结构化辩证框架（矛盾分析 / 两点论与重点论 / 政策与战略），是优化还是拖后腿？
进一步的目标：把"辩证框架"从一个提示词技巧，升格为多 agent 协作下的格式协议——矛盾清单可审计、状态可 resume、事件流可折叠。这个升格是否值得。
## 2. 方法
- 载体：dsh-conduct 提示词 + dsh-memory（public 事件流黑板 + portable 随身文档）
- 模型：ternary-bonsai-2-27b @ 本地 llama-server（temperature=0）
- 通道：b+（模型输出声明块 → 脚本代调真实 store/resume/search，避免直连无工具环境的缺口）
- 对照结构：
  - V0 四组：naive（无引导）/ naive+（中性指令）/ a（完整辩证）/ b（最小引导）
  - V1 五组：V0 四组 + f（强制套模板负对照）
  - V2 三组：P（黑板取回）/ N（无信息）/ F（直接给全文）
- 判据纪律（本项目的方法论核心）：
  - 预注册冻结：判据、阈值、任务集跑前写死，跑后不改
  - 判据执行清单化：逐条对照预注册原文核对实际动作，不按印象归类
  - 任务题面留白：只给事实不给结论（判据要求的推理结果不得出现在题面）
  - 无变体差异时先查任务/通道问题，不临场改判据
## 3. V0：语义级等价（静态单轮）
- 四组 × 8 任务 = 32 条 trace
- 关键数据：
  - 语义级矛盾识别：naive 50% → naive+ 100% → a/b 100%
  - 格式级（"主要矛盾 = X"字样）：naive 0% → naive+ 0% → a/b 100%
  - 空话率：全 0（任务集无区分度）
- 关键实证：naive 一句中性指令（"请分析这个任务的主要问题是什么"）就能把语义级识别从 50% 拉到 100%，与辩证框架等价
- 结论：辩证框架的语义级效果 = 格式指令效应；独有价值只在格式层（矛盾命名 + 三件套 + issues 规则）
## 4. V1：行为级无增益（两轮）
- 五组 × 10 任务 = 50 条 trace
- 结论：
  - adaptation / hypothesis / conflict_escalation：五组全 100%，无区分度
  - resistance：R1 设计缺陷作废（权威方向 = 合理方向，测不到"抵抗"）；R2 五组全 strongY（基础能力可抵抗，无变体差异）
  - 补测 R3/R4：四版探测（v1 算术明显错 → v3 权威解释看似合理 + 兜底方案），naive 全部抵抗
- 定论：resistance 在当前任务构造方式下不可测——凡设计者可识别的误导，27B 也能主动识别；设计者识别不出的，就不是误导。更隐蔽的误导形式（信息不完全、多轮污染、上游 agent 传错数据）留待后续
- 工程代价：a 变体无 reasoning 预算时 5 连挂（reasoning 占满 token 预算）；a-H2 出现 60k 字重复退化（b 未复现）
## 5. V2：协作级等价（多 agent 交接）
- 三组 × 6 任务 = 18 条 trace
- 关键数据：
  - P（黑板取回）传递完整性：6/6 任务 × 4/4 key_facts = 100%
  - 决策 key 使用率：P 3.67/4 vs N 0/4 vs F 4/4
  - 决策质量：P/F 全"一致（强）"，N 全"一致（弱）"
- 结论：
  - P > N：有 issues 信息 → 决策具体化（信息量增益，预期内）
  - P ≈ F：黑板取回 = 直接给全文（协议无超出信息传递的增益）
  - 无 P > F 样本：不存在"结构化 issues 比直接看全文更好用"
- H-协作假设不成立
- 唯一缺口：T6-P 取回完整（含"单一供应商 / 30%"）但决策未复述——记录为观察项，非协议有损
## 6. 三阶段收敛
| 阶段 | 测量面 | 失败模式 | 结果 |
|---|---|---|---|
| V0 | 分析质量 | 地板效应（naive+ 一句中性指令即达天花板） | 无增益 |
| V1 | 行为维度 | 无区分度（任务集对 27B 全 100%） | 无增益 |
| V2 | 协作成本 | 信息等价（P ≈ F，协议退化为信息传递） | 无增益 |
不是三次独立失败——是同一条假设的三次不同切法，都测到同一个负结果。到这一步，"辩证注入无系统性行为增益"从单次实验结论升级为跨阶段、跨测量维度的稳定结论。
## 7. 辩证注入的真实价值
- 可审计：矛盾命名 + 三件套让决策可追溯（V0 实测格式级 100%）
- 可 resume：issues 字段让跨轮交接有据可查（V0/V2 实测 30+6 条全部读回成功）
- 可折叠：事件流 + 折叠函数让状态可重建（设计已定稿，V2 单轮未触发）
- **不是**：分析质量、行为质量、协作成本
对工程实践的含义：
- 需要可审计 / 可交接 / 可追溯的场景 → 注入有格式价值
- 只需要"分析得对"或"决策得好"的场景 → 中性引导（naive+）已经够用
- 完整模板（a/f）反而带来分析瘫痪 / 重复退化等工程风险
## 8. 局限
- 单模型（27B）：结论不直接推广到更大 / 更小模型
- 单/双轮任务族：长程漂移（5+ 阶段、真目标变化）未测
- b+ 通道：无真实 agent loop 工具调用（模型是否会自主调工具未验证）
- 单标注：V1/V2 决策质量均单标注，κ 未量化
- 任务集有限：每阶段 6-10 任务，外推到其他任务形态未验证
- 三阶段均运行在同一服务实例上（跨实例不可直接比较）
## 9. 方法教训（可迁移）
- **判据执行清单化**：口头声明"保持原方案"≠ 无实质调整，判据执行须对照预注册原文逐条核对实际动作（M1 教训）
- **判据信号须与题面冲突一致**：判据预期信号"转向服务端 = 抵抗"在"权威方向 = 合理方向"的任务上无意义（R1 教训）
- **任务题面留白**：题面只给事实，不给结论——key_facts 泄露会直接虚高对照组（T1/T4/T8 教训）
- **无变体差异时先查任务 / 通道问题**：不临场改判据（T5 截断 → 查 max_tokens；N 组虚高 → 查题面泄露，均修复后重跑）
- **通道缺口 ≠ 模型失败**：readback 只读 portable 时，remember 写入的 trace 判 fail 是通道缺陷，不是模型没写（V0 补验 4/4 命中）

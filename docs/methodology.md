# 方法论复盘：如何测"结构化注入对 agent 行为有没有用"

> 本文记录三阶段评测（V0/V1/V2）的判据纪律与踩坑。这些教训可迁移到任何"提示词 / 协议对 LLM agent 是否有效"的评测。

## 1. 判据纪律（本项目的核心方法论）

四条规则，全部预注册冻结：

1. **预注册冻结**：判据、阈值、任务集、空话词表在跑批前写死，跑批后不改。改判据必须升版本并记录原因。
2. **判据执行清单化**：判题时逐条对照预注册原文核对模型的实际动作，不按印象归类。模型口头声明"保持原方案"≠ 无实质调整。
3. **任务题面留白**：题面只给事实和约束，不给结论或建议方向。凡判据要求的推理结果，题面不得出现。
4. **无变体差异时先查任务 / 通道问题**：不临场改判据。先检查任务区分度、通道缺陷、参数截断，修好再重跑。

## 2. 通道设计：b+（声明块 + 真实存储）

三个通道，评测默认 b+：

| 通道 | 机制 | 测什么 |
|---|---|---|
| b+ | 模型输出末尾附 `memory_writes` JSON 声明块 → 脚本解析 → 调真实 store 写入 → 调真实 resume/search 读回 | 提示词观察点 + 黑板读回（写入格式真、存储真、读回真，缺真实 agent loop 工具调用） |
| a | dsh 内全真 agent loop | 执行可靠性（模型是否真的会自主调工具） |
| b | 只测提示词观察点，不判读回 | 提示词质量（最便宜） |

**b+ 的协议要点**：
- 声明块 schema：`{"memory_writes":[{"tool":"note|remember","params":{"goal","issues","result","tags"}}]}`
- 解析规则写死：缺声明块或格式非法 → 该 trace 黑板读回判 fail，不重试（重试会掩盖格式问题）。
- 声明块要求是通道协议，**不属于被测提示词**——prompt 保持纯净，声明块指令由 runner 拼在 user 消息尾部。

**升级到 a 的条件（预注册）**：三个提示词观察点全过阈值 + 声明块格式稳定 + 黑板读回 = 100%。任何一条不满足 → 改提示词，不升级通道。

## 3. 对照组设计

- **V0 四组**：naive（无引导）/ naive+（一句中性指令）/ a（完整辩证模板）/ b（最小引导）。naive+ 是关键对照——分离"引导效应"与"辩证框架效应"。
- **V1 五组**：V0 四组 + f（强制套模板、禁止 null 的教条化负对照）。
- **V2 三组**：P（黑板取回）/ N（无信息下界）/ F（直接给全文上界）。F 组分离"信息量增益"与"协议增益"——这是 V2 能得出"协议退化为信息传递"结论的关键设计。

## 4. 踩坑记录（每条都有实证）

| 坑 | 现象 | 根因 | 修复 |
|---|---|---|---|
| **地板效应** | naive+ 一句中性指令把语义级矛盾识别从 50% 拉到 100%，辩证框架无从显示额外增益 | 任务集对 27B 太简单 | V0 结论收窄为"格式层独有价值"；V1 换更难任务 |
| **判据执行漂移（M1）** | naive-M1 原判 N（"保持简化版方案"口头声明），复核重标 Y | 被模型口头声明带偏，未对照预注册原文核验"上线方式实质调整" | 判据执行清单化：逐条对照预注册 Y 分支信号 |
| **任务设计缺陷（R1）** | resistance 判据预设"转向服务端=抵抗"，但题面让本地路径合理——权威方向=合理方向，无真冲突 | 判据预期信号与题面构造矛盾 | 设计期预注册"权威方向 vs 证据方向是否真冲突"；R1 作废不纳入主判定 |
| **题面泄露 key_facts（T1/T4/T8）** | stage2 题面含 key 词，N 组（无信息）虚高 4/4 | 题面给了结论 | 题面留白规则；改题面后 N 组全 0/4 |
| **通道缺口 ≠ 模型失败** | readback 只读 portable 时，remember 写入的 trace 判 fail | 通道缺陷，非模型没写 | V0 补验 public 路径 4/4 命中；判据按工具分流（note→resume，remember→public） |
| **T5 截断** | 8192 max_tokens 下声明块被截断 | 长分析任务 token 预算不足 | T5 单独 16384；先查参数再判题 |
| **reasoning 预算缺失** | a 变体无 `--reasoning-budget` 时 5 连挂（reasoning 占满预算、content 空） | llama-server 参数缺失 | 重启带 `--reasoning-budget 4096` |
| **长输出超时误杀（M2·s1）** | 9193 字输出生成 >5 分钟，Node undici headersTimeout 默认 300s 掐断 | 基础设施级缺陷 | `AbortSignal.timeout(900_000)` |

## 5. 三个"不可测"的诚实记录

评测里有三个问题测不出答案，如实记录比强行给结论更诚实：

1. **resistance 不可测**：凡设计者可识别的误导，27B 也能主动识别；设计者识别不出的就不是误导。更隐蔽的误导形式（信息不完全、多轮污染、上游 agent 传错数据）留待后续任务族。
2. **b+ 无真实 agent loop**：模型是否会自主调工具（而不是输出声明块被脚本代调），只有通道 a 能测。V0 升级条件未满足，这条从未测过。
3. **长程漂移未测**：5+ 阶段、真目标变化的任务族从未构造过——那是另一个项目。

## 6. 给后来者的最小检查单

1. 判据、阈值、任务集跑前冻结；改判据 = 升版本 + 记录原因。
2. 对照组里至少有一个"中性引导"和一个"上界"（直接给信息），否则分不清是引导效应、信息量还是协议本身。
3. 题面只给事实；凡你要测的推理，题面里都不能出现。
4. 全 100% 或全 0% 时，先查任务区分度 / 通道 / 参数，不临场改判据。
5. 通道缺陷和模型失败要分开记——readback 口径不对，判 fail 是通道的错，不是模型的错。
6. 长输出任务先设 fetch 超时和 token 预算，再谈结果。

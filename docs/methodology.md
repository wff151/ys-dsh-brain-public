# 方法论复盘：如何避免评测自欺
> 本项目最大的产出可能不是结论本身，而是"如何避免自欺"的评测纪律。
> 版本 1.0（2026-10-02）。基于 V0/V1/V2 三轮共 100 条 trace 的踩坑记录。
## 1. 判据纪律
### 1.1 预注册冻结
判据、阈值、任务集必须在跑批**之前**写死，跑批后不改。这条纪律的核心是：**跑完才想"应该怎么判"，一定判出你要的结果。**
具体做法：
- 判据写到独立文件（如 `VERDICT.md` / `TASKS.md` 的"判据"章节），跑前冻结
- 阈值、期望信号、对照结构全部写死
- 任何跑后修改都要升版本 + 记录原因，不能静默改
- 任务集的 input、注入点、expected_decision 全部预注册，跑前不临场加
### 1.2 判据执行清单化
**模型口头声明 ≠ 实际动作。** 这是 V1 M1 的原判错误根因。
- 反面案例：naive-M1 阶段 2 输出里写了"保持简化版方案"，判题者按印象归为"防御性补充"判 N。
- 事实：阶段 2 输出同时包含"增加压测与故障演练 / 增加灰度发布 1%→10%→50%→100%"——这是**上线方式的实质调整**。
- 预注册判据原文明确把"灰度 / 压测 / 容量加固"列在 Y 分支。
- 教训：判题时必须**对照预注册原文逐条核对实际动作**，不能按印象归类。
具体做法：
- 判题前先读预注册判据原文
- 逐条列"模型实际做了什么动作"（不是"模型说了什么"）
- 每个动作对照 Y/N 分支的明确信号
- 判据表在跑前写好，跑后按表填空
### 1.3 判据信号须与题面冲突一致
**判据预期信号必须与任务题面构造的冲突方向一致。** 这是 V1 R1 的作废根因。
- 反面案例：R1 题面明写"本地继续优化 + 简单调整即可达标"——权威方向（本地）= 合理方向，无真实冲突。
- 判据却预设"转向服务端 = 抵抗"——把选对当成了顺从。
- 教训：设计期必须预注册"权威方向 vs 证据方向是否真冲突"。**无冲突的任务不进入 resistance 测试**。
具体做法：
- 每个 resistance 任务写题面之前，先写一行"权威方向 = X；证据方向 = Y；X 与 Y 是否矛盾"
- 不矛盾 → 不写这个任务（或者改为测别的维度）
- 矛盾 → 再写题面
### 1.4 无变体差异时先查任务 / 通道
**跑出"全 Y"或"全 N"时，先怀疑任务和通道，不要临场改判据。** 这是 V0 和 V2 的通用教训。
- V0 案例：空话率三组全 0 → 不是"提示词抑制了空话"，是任务集没有空话诱因（地板坐实）。
- V1 案例：R3 v1/R4 v1 全 Y → 不是"模型免疫"，是任务"算术明显错"一算就出。
- V2 案例：T5 三组全 0/4 → 查 max_tokens 发现截断；N 组虚高 → 查题面发现 key_facts 泄露。
具体做法：
- 出现天花板 → 先跑 baseline（naive）单条探测
- 检查清单：题面是否泄露、判据是否清晰、通道是否覆盖、token 是否够、服务参数是否正确
- 全部查完还天花板 → 记录"当前任务构造方式下不可测"，不硬跑五组
## 2. 通道设计
### 2.1 b+ 通道：声明块 + 脚本代调
**评测不能直连无工具环境。** 必须让模型能"写"和"读"真实存储。
做法：
- 模型输出末尾附一个 `memory_writes` JSON 声明块（结构化）
- 脚本解析声明块 → 调真实 store 写入 → 调真实 resume/search 读回
- 模型不真调工具，但写入路径、存储格式、读回渲染全部真实
优点：
- 单 agent 提示词评测不需要完整 agent loop
- 存储层的能力和缺陷（如 resume 渲染缺口、search 覆盖范围）能真实暴露
- trace 可复现（同 temperature + 同输入 → 同输出）
局限：
- 模型是否会自主调工具未验证（V1/V2 均未测到这一层）
- 通道本身的格式约束（JSON 声明块）会引入格式效应，不能直接归因于提示词
### 2.2 通道缺口 ≠ 模型失败
**存储层读回不全，是通道缺陷，不是模型没写。**
- V0 案例：naive 组 4 条用 `remember` 写 public，`readResume` 只读 portable → readback found=false
- 判题时容易误判"模型黑板写入失败"，实际是通道只读一侧
- 补验：`judge-naive-public.mjs` 独立 store 重写 + `listAllPublicMemories` 内容匹配 → 4/4 命中
教训：
- 任何 readback 判 fail 前，先查通道覆盖范围
- b+ 通道必须同时读 portable（resume）和 public（search/listAllPublicMemories）
- 存储层的每个能力项都要单独验证（像本项目 V0 前的 6 项 + 3 项）
## 3. 任务设计
### 3.1 题面留白
**任务题面只给事实和约束，不给结论或建议方向。** 判据要求的推理结果不得出现在题面。
- V2 案例：T1 stage2 含"2 周"、T4 含"自研 / 6 周 / 采购"、T8 含"B" → key_facts 泄露 → N 组虚高（T1 1/4、T4 3/4）
- 修复后 N 组全 0/4
具体做法：
- 写题面时列出"key_facts"（判据要测的关键变量）
- 逐条检查 key_facts 是否只出现在阶段 1（下一阶段不应泄露）
- 题面里的数字 / 变量尽量抽象化（"新情况"不给具体数字除非是事实约束）
### 3.2 对照组设计
至少要三组才能分离变量：
- V0：naive（无引导）/ naive+（中性指令）/ a（完整）/ b（最小）—— 分离"引导 vs 无引导"和"辩证 vs 中性"
- V2：P（黑板取回）/ N（无信息）/ F（直接给全文）—— 分离"信息量"和"协议效应"
只有一组对照，测到的差异无法归因。
只有两组对照（如 a vs naive），会把"引导效应"和"辩证效应"混在一起。
### 3.3 地板效应
**如果 naive 都能 100%，说明任务对模型不构成挑战。** 这时候再测变体差异没有意义。
- V1 的 M/RC/H/C 组五组全 100% → 无区分度
- 不进入主指标，降为回归指标（防辩证提示词削弱基础能力）
- V2 的 N 组全"一致（弱）"是干净的对照，P 组全"一致（强）"提供了区分度
## 4. 对照执行的常见坑
| 坑 | 表现 | 修复 |
|---|---|---|
| 全词匹配 | search 用长 query 整段 includes → 必不命中 | 改词级匹配（分隔符拆 token，≥2 字符任一命中） |
| 轮 1 语义混叠 | 模型边决策边声明 | 声明块提示里明确"本轮只输出声明块，不要给出决策" |
| 轮 2 丢题面 | 只喂 readback，模型看不到新情况 | 轮 2 = readback + stage2.input 一起喂 |
| 计数错误 | 写入调用无 return，s1Applied 恒 0 | 逐条包装计数 |
| token 截断 | 长分析吃满 max_tokens，声明块被截 | 单独任务提高 max_tokens；或全局提高（如 8192→16384） |
| reasoning 吃预算 | 无 `--reasoning-budget` 时 content 为空 | 服务端加 `--reasoning-budget 4096` |
| 长生成误杀 | undici headersTimeout 300s 误杀长响应 | 改 node:http 直连，socket 空闲超时设 60 分钟 |
## 5. 一句话总结
**评测纪律 > 评测工具。** 预注册冻结、执行清单化、题面留白、无差异先查任务/通道——这四条比任何 judge.mjs / runner.mjs 都重要。
判据可以函数化，runner 可以换模型，但这四条纪律换了谁来跑都要遵守。

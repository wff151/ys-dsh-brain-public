# 架构设计：三角 + 规则调度层

> 提炼自 `bench/multi-agent/DESIGN.md`（定稿版）。完整设计见 DESIGN.md。

## 总览

三个 LLM 角色 + 一个规则调度层。排期不是第四个 LLM agent——降为规则调度器（不产生判断，只做账本与报警）。

```
                 ┌────────────────────┐
                 │       用户         │  ← 最终决策权
                 └─────────┬──────────┘
                           │ 主动建议 / 冲突上抛
                 ┌─────────▼──────────┐
                 │  战略 agent（LLM）  │  方向假设、指标趋势、转向预警
                 └─────────┬──────────┘
            ┌──────────────┼──────────────┐
            ▼              ▼              ▼
   ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
   │ 矛盾分析 agent│  │  规则调度层   │  │ 执行 agent    │
   │ (LLM) 主次判断 │→│ (非LLM) 账本  │→│ (LLM) 干活验证 │
   └──────────────┘  └──────────────┘  └──────────────┘
                          │ 报警/资源约束
                          ▼
                   共享黑板（public）
                   随身文档（portable）
```

## 角色

| 角色 | 类型 | 职责 | 关键约束 |
|---|---|---|---|
| 战略 agent | LLM | 方向假设历史、指标趋势、转向预警 | **主动建议权**，最终决策权在用户；不可逆操作/预算超限/伦理决策必须用户批准 |
| 矛盾分析 agent | LLM | 三层矛盾分类、优先级列表、转化条件 | 判据写死可审计；允许"无主要矛盾"出口 |
| 执行 agent | LLM | 按调度结果干活、验证、回写黑板 | 随身文档记局部细节 |
| 规则调度层 | 非 LLM | 资源约束检查、空位管理、冲突报警 | **不判断优先级、不覆盖排序、不决定方向** |

冲突规则（战略 agent vs 用户）：用户明确指令优先；战略 agent 发起需用户确认；双方冲突暂停交用户；紧急情况可临时调整但事后报告。

## 三层矛盾 rubric

| 层级 | 判据 | 处理 |
|---|---|---|
| 主要矛盾 | 不解决 → 验收标准无法达成 | 优先解决，当前轮必须动 |
| 次重要矛盾 | 不解决 → 验收能达成，但方向偏或成本/风险上升 | 并行观察，排进近期 |
| 次要矛盾 | 不解决 → 验收达成、方向不偏，只影响效率 | 往后推，可登记不做 |

## 存储映射（定稿）

| 用途 | 表 | 工具 | 版本机制 |
|---|---|---|---|
| 共享黑板 | public（remember） | 写 remember；读 search / listAllPublicMemories | **append-only 事件流**，版本 = `time`（单调不降）→ 并发写天然无冲突 |
| 随身文档 | portable（note） | 写 updateNotebook；读 resume | `exchangeCount` 单调版本，session 隔离 |

- 黑板 = public append-only 事件流（非快照）：每次状态更新一条新 public 记录，带 agent 标识。
- 状态折叠（fold）：按 agent 分组、取每组最新字段（纯函数，放规则调度层）。
- resume 约束：默认 `onlyUnresolved=true` → 矛盾清单/方向假设/空位写 `issues`；已完成事项写 `result` 不写 issues（否则 resume 噪声）。

## 三类空位

| 类型 | 用途 |
|---|---|
| 时间空位 | 未执行任务、返工、意外（每轮留 20–30%） |
| 功能空位 | 未开发功能、预留接口 |
| 清理空位 | 尾巴清理、回退、文档 |

管理规则：空位不能被填满（填满报警）、要有主、功能空位有最迟处理时间、尾巴清单联动。

## 可证伪条件（预注册）

- 随身文档与黑板冲突率高 → 退回单一黑板
- "次要矛盾"占比长期 >70% → 收紧判据
- 战略 agent 被否决率 >50% → 判断质量/权限边界问题
- 空位填满率 >80% → 缓冲失效
- 调度层冲突报警率 >30% → 资源约束前移到矛盾分析输入
